# 长期运行内存泄漏修复验证

环境：Apple Silicon，macOS 26.6，.NET SDK 10.0.403，Avalonia 12.1.4。

## 原因与复现

本机原进程 PID 76527，2026-11-05 11:10 启动。18:26 的 `vmmap -summary` 显示物理内存占用 76.2 GiB；`heap` 检出 10,486,571 个 `AvnAccessibilityElement` 和同量级的自动化节点。原进程退出前，`proc_pid_rusage` 测得物理内存占用 96,225,317,672 字节，约 89.6 GiB。

采样主线程时，热点是无障碍子节点重建和 GC。官方原生库取得托管 automation peer、children array 等 COM 接口后没有释放，并且原生元素与节点存在生命周期循环，导致已移除控件及其数据不能回收。应用每次快照均重建最多 500 条日志控件，持续放大该缺陷。

使用独立 Debug 应用，反复创建、遍历无障碍树并移除控件，再检查弱引用：

| 场景 | 结果 |
| --- | --- |
| 官方 12.1.4 原生库 | 5/5 个已移除控件仍存活，退出码 1，重复运行结果一致 |
| 固定版本源码加原生生命周期补丁 | 0/5 个已移除控件存活，退出码 0 |
| 保留托管控件，反复移除、隐藏时修改、重新挂载 | 通过，无崩溃，无障碍元素正常重建 |
| 相同快照重复发布 | 修复前 3 次产生 1,509 次集合通知；修复后为 0 |
| 日志达到 500 条再追加 | 仅移除最旧一条并插入最新一条，顺序正确 |
| 连续发布 10,000 次快照 | 仅应用最后一次 |
| 销毁时存在待处理快照，销毁后再次发布 | 均不再更新界面 |

回归使用真实 macOS 原生后端，独立生命周期，不读取用户设置、发现真实 Herdr 会话或访问 Clash。GC 强制回收只用于弱引用检查。

## 构建与兼容

- 锁定依赖还原成功；Release 全量构建成功。
- 原有 264 项测试全部通过。
- `win-x64` 目标编译成功；本次没有 Windows 实机运行验证。
- macOS arm64 / x86_64 通用原生库编译成功；Intel 仅编译验证。
- 安装包与安装目录中的原生库 UUID 均与修复产物一致，两种架构一致；应用通过 `codesign --verify --deep --strict`。

原生库来源、补丁和构建说明见 [native/avalonia](../native/avalonia/README.md)。未升级托管依赖或改变业务协议。

## 本机更新与观察

为释放仍在增长的旧进程内存，在核心回归、全量测试和初步窗口压测通过后先完成本机更新，30 分钟隔离压测继续运行。

- 旧应用备份：`/Applications/Herdr Auto Continue.app.backup.20261105-185619`。
- 新应用 PID 69077，18:57 重启；界面确认监控中、已连接 1 个会话及 7 个 agent，代理长连接正常。
- 真实应用首次无障碍遍历后，原生堆为 294 个 `AvnAccessibilityElement`、295 个自动化节点。
- 30 分钟隔离压测通过：连续 1,800.02 秒，17,654 次刷新，357 次采样，最大采样间隔 5.60 秒。前台、最小化、隐藏及恢复均覆盖；滚动保留 500 条日志，未强制 GC。
- 压测物理内存峰值 543.4 MiB，结束时 460.7 MiB；预热 10 分钟后净增 14.4 MiB，低于 100 MiB 验收上限。最后 10 分钟可见窗口为 460.5～475.0 MiB，当前树的无障碍节点约 2,763 个。
- 本机验收结束时仍为单实例，服务监控中、代理正常，界面持续刷新；此时物理内存约 396.6 MiB，已正常运行约 45 分钟。
- 8 小时真实进程观察：18:58 启动，后台运行中；尚未完成，不作为已通过的长期验证。

本地原始结果位于 `dist/memory-stock-2026-11-05/`、`dist/memory-regression-2026-11-05/`、`dist/memory-soak-final-2026-11-05/`。早期被诊断工具暂停的压测及辅助程序重复回调的试跑均未计入验收；最终连续测试已修正辅助程序并完整重跑。

真实进程观察的 `dist/memory-live-2026-11-05/summary.json` 实时更新，`samples.jsonl` 保存每分钟的物理内存指标，以及每小时的原生堆对象数量。压测中的当前树节点数与原生堆中全部分配对象数分别记录，不混用。观察程序不自动终止或重启应用。
